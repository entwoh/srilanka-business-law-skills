## Findings and top 10 token-saving opportunities

_Hand-written analysis (preserved on regeneration). Baseline taken 2026-09-24 on branch
`refactor/graph-architecture`, before any content change._

### What the numbers say

- **Always-loaded cost is already low (529 tokens) — the problem is the opposite.** Nine of
  ten descriptions are 11–15 words (97–120 chars) and name no forms, vernacular or triggers
  ("Form 15", "BR", "EPF number", "Pvt Ltd"). They will under-trigger. The ≤1,300-token
  target in the plan leaves room for ~90-word descriptions, so Phase 6/11 will *raise*
  always-loaded tokens by ~2× on purpose. Only `intellectual-property` (111 words, 715 chars)
  follows the authoring guide.
- **SKILL.md bodies give the model no routing.** Nine are an 8-line paragraph that links to
  every reference file. The model cannot tell which file answers the question, so the
  realistic per-query load is closer to the **full-skill load (mean 4,141 tokens)** than the
  typical-load estimate (mean 1,482).
- **Sections are already small.** 268 H2 sections across the references: mean 130 tokens,
  median 114, max 470, **none over 600, 109 under 100**. Phase 3 is mostly *merging*
  fragments into answer-sized nodes, not splitting.
- **About 5,700 tokens of every-read overhead are aimed at maintainers, not at answering:**
  reference frontmatter (~2,400), "Unverified draft" banners in 18 files (~1,300),
  "Verification needed" checklists (~2,000).
- **Portability is broken today.** 24 links leave their skill folder (all cross-skill; the
  only `../../shared` reference is also the **one broken link**:
  `skills/shares-and-capital/references/share-issues.md` → `../../shared/roc-forms-index.md`,
  which resolves to `skills/shared/…`). No skill links to `shared/` at all, so the 5,479
  tokens of shared indexes are unreachable from any installed skill.

### Top 10 opportunities (rough saving per single-domain query in brackets)

1. **Router SKILL.md + `_map.md` + section reads (L1→L2→L3).** Replace "read the references"
   with a decision tree and a map. Reading 1–3 nodes (~130–400 tokens) plus a ~1k map instead
   of 2–5 whole files. [~4.1k → ~1.3k, ≈65–70%]
2. **`kg.py find` → `kg.py read`** when code execution is available: skips even the map.
   [~1.3k → ~0.5k]
3. **Move maintainer metadata out of the read path.** Compile frontmatter into node fields
   (`verified`, `source`, `status`), turn the "Unverified draft" banner into
   `status: draft` + a one-line caveat in the answer format, and move "Verification needed"
   checklists into `REVIEW-TODO.md`. The legal caveat *must* still be surfaced — it moves
   from repeated prose to node metadata the answer format always prints. [~5.7k repo-wide;
   ~200–300 per file read]
4. **Canonical shared entities (Phase 2).** "Companies Act No. 7 of 2007" is written out 21
   times, Form 6 18×, Form 15 14×, ROC 67×. The audit finds 45 differently-written statute
   names (e.g. "VAT (Amendment) Act" and "Value Added Tax (Amendment) Act"; "EPF Act" and
   "Employees' Provident Fund Act"). One node each, with aliases, and references by ID.
5. **Split the shared indexes into per-entity nodes.** `roc-forms-index.md` (1.6k tokens)
   answers "which form for X" in ~40 tokens once each form is a node.
6. **Deduplicate the cross-skill copies found by the audit** (≈860 tokens): the compliance
   deadline table in `company-formation/post-incorporation.md` vs `annual-return.md` /
   `tax-compliance/filing-calendar.md`; reckless trading in `directors-duties.md` vs
   `insolvency.md`; ROC address/forms/fees URLs duplicated in two shared files; model Articles
   in the glossary vs `incorporation-checklist.md`. Keep one owner, add `RELATED` edges.
7. **Rewrite the descriptions for triggering, not size** — vernacular, form numbers,
   "Sri Lanka" explicitly, Singlish phrasings — and trim `intellectual-property` to ≤90 words.
   (Negative cost, positive accuracy: fewer missed triggers means fewer wrong answers.)
8. **TL;DR-first sections** so the model can stop after two lines for yes/no, deadline and
   "which form" questions. [~50% of a node read on simple questions]
9. **Cross-domain playbooks** for the multi-skill journeys (formation → BO → EPF/ETF → tax;
   foreign share issue → IIA → Form 6 → BO). Today these need 3–4 skills × full loads
   (~12–16k tokens). [→ ~2k]
10. **Self-contained `dist/` builds with stub nodes** fix the 24 escaping links and the
    broken `shared/` path. A cross-skill hop becomes "use skill X, node Y" instead of a dead
    relative path.
